# 仓库系统 · Cloudflare 部署教程

本教程教你怎么把 `cloudflare/` 这个版本（前端 `index.html` + 后端 Pages Functions + D1 数据库）部署到 Cloudflare，让用户通过网址直接访问、录入和盘点。

> 适用对象：本项目已生成的 `cloudflare/` 目录。无需改任何前端代码，后端用的是 Cloudflare 原生的 **Pages Functions + D1（serverless SQLite）**。

---

## 一、准备环境

只需要两样东西： 

1. **一个 Cloudflare 账号**（免费就行）：https://dash.cloudflare.com/sign-up
2. **Node.js ≥ 18**（你机器上已经有了，终端里 `node -v` 能看到版本即可）

不需要安装数据库软件——D1 是 Cloudflare 托管的服务，数据库在云端。

---

## 二、安装并登录 Wrangler（Cloudflare 命令行）

打开终端（项目里用 Git Bash / PowerShell 都行），在项目**根目录外任意位置**执行：

```bash
# 全局安装 wrangler（Cloudflare 官方 CLI）
npm install -g wrangler

# 验证安装
wrangler --version
```

登录你的 Cloudflare 账号（会弹浏览器授权）：

```bash
wrangler login
```

登录成功后会显示你的账号信息。

---

## 三、创建 D1 数据库

数据库叫 `warehouse`（名字随意，和后面配置一致即可）：

```bash
wrangler d1 create warehouse
```

命令会输出一段信息，里面有一个 **`database_id`**，类似：

```
✅  Successfully created DB 'warehouse' with id: xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
```

**把这个 id 复制下来**，下一步要用。

---

## 四、填到配置文件里

打开 `cloudflare/wrangler.jsonc`，找到这一行：

```jsonc
"database_id": "REPLACE_WITH_YOUR_D1_ID"
```

把占位符换成你刚复制的 id：

```jsonc
"database_id": "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
```

> 表结构（`items` / `movements` / `settings` / `backups`）会在**第一次访问时自动建好**，不用手动跑 SQL。

---

## 五、本地预览（先在电脑上跑通）

```bash
cd G:/仓库网站/cloudflare
wrangler pages dev .
```

终端会给出一个本地地址（默认 `http://localhost:8788`）。浏览器打开它：

- 点中间的 **＋** 添加物品，填编码、仓库、数量，保存；
- 列表里点物品 → 取出 / 编辑 / 删除；
- 切到备份页导出 JSON，确认数据能存能取。

本地预览用的就是云端同一个 D1 数据库（前提是 `database_id` 已填好），所以预览时录入的数据，部署后也在。

> 想用完全独立的本地库测试、不碰线上数据，可改成：
> ```bash
> wrangler pages dev . --d1 DB=./local-preview.sqlite
> ```

---

## 六、正式部署上线

确认本地跑通后，发布到 Cloudflare：

```bash
cd G:/仓库网站/cloudflare
wrangler pages deploy .
```

部署完成后，终端会给出一个网址，通常是：

```
https://warehouse-cloudflare.<你的子域>.pages.dev
```

把这个链接发给那 10 个同事，他们打开就能用了——**无需登录，所有人直接录入**。

### 绑定自己的域名（可选）

想要 `ku.你的域名.com` 这种地址：

1. 在 Cloudflare 控制台把你的域名 DNS 托管到 Cloudflare；
2. 进入 **Workers & Pages → 你的项目 → Custom domains**，添加域名并按提示加一条 CNAME 解析；
3. 等几分钟生效即可。

---

## 七、以后改了代码怎么更新

只要重新跑部署命令：

```bash
cd G:/仓库网站/cloudflare
wrangler pages deploy .
```

Cloudflare 会生成新版本并立刻生效，数据（在 D1 里）不受影响。

---

## 八、把旧数据迁过来（如果你之前在别的版本录过数据）

前端自带导入/导出，最省事：

1. 在**旧系统**备份页点「导出 JSON」，下载 `仓库数据.json`；
2. 在**新部署好的 Cloudflare 版**备份页点「导入 JSON」，选这个文件；
3. 物品和出入库记录就整体搬过来了。

> 注意：导入会**整体替换**当前数据，迁移前先确认新系统是空的或确认要覆盖。

## 九、费用与额度（免费版够用）

| 项目 | 免费额度 |
|---|---|
| D1 读 | 500 万次 / 天 |
| D1 写 | 10 万次 / 天 |
| D1 存储 | 5 GB |
| Pages 请求 | 10 万次 / 天 |
| Pages 带宽 | 10 GB / 月 |

10 个人的小仓库，连零头都用不到。

## 十、常见坑

- **`database_id` 没填 / 填错** → 部署或运行时会报 D1 binding 找不到。回到第三步重新 `wrangler d1 create` 或 `wrangler d1 list` 查 id。
- **`wrangler login` 打不开浏览器** → 用 `wrangler login --browser false`，它给你一个网址手动粘贴授权码。
- **本地预览白屏** → 确认终端是在 `cloudflare/` 目录下跑的 `wrangler pages dev .`，且 `index.html` 在该目录根。
- **改了 wrangler.jsonc 不生效** → 重新 `wrangler pages deploy .`。

---

## 十一、一个重要提醒（国内访问）

Cloudflare **免费版在中国大陆访问可能不稳定、被限速甚至打不开**（控制台能进，但网站实际访问不稳）。Cloudflare 的中国 CDN 是企业版付费能力。

- 如果用户**在海外**或能走代理 → 这版直接可用；
- 如果用户**都在国内要稳定直连** → 更推荐走之前做好的 **EdgeOne 版**（`edgeone/` 目录），国内访问更稳。

两个版本前端完全一样，只是后端托管不同，按访问场景二选一即可。

---

## 目录结构速查

```
cloudflare/
├── index.html              # 前端（无需改动）
├── wrangler.jsonc          # Pages + D1 配置（填 database_id）
├── package.json            # dev / deploy 脚本
└── functions/
    └── api/
        └── [[route]].js     # 后端：/api/* 全部接口，数据存 D1
```

部署核心就三步：**`wrangler login` → `wrangler d1 create warehouse` 填 id → `wrangler pages deploy .`**。
